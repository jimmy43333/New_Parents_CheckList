# 手機版分頁列改為固定底部導覽列

**Status**: accepted

手機版(≤700px)原本沿用桌機版「頁首下方橫向分頁列」的位置與樣式,但這在單手持機時不符合拇指熱區,與現有 700px RWD 斷點慣例(觸控目標優化)的初衷不一致。因此決定:手機版改用 `position: fixed` 貼於螢幕底部的原生 App 風格導覽列(icon 在上、label 在下,3 個分類平均分佈,選中狀態僅用色彩變化而非背景色塊),沿用同一個 `TabBar.vue` 元件,只在 700px 斷點內用 CSS 改變其定位與排版,不拆成獨立元件;桌機版位置與樣式維持不變。

## Considered Options

- **同元件、CSS 依斷點切換定位**(採用):維護成本低,分頁的 active/count 邏輯只有一份。
- **拆成獨立的 `BottomNav.vue` 元件**:排版彈性更高,但會產生兩份幾乎重複的分頁邏輯與雙重維護成本,予以否決。
- **維持跟隨捲動、不固定貼底**:實作最簡單,但失去「隨時可切換分頁」的手機導覽價值,予以否決。

## Consequences

- 進度徽章從「已完成/總數」文字改為「剩餘未完成數量」的小圓點,全部完成時徽章消失——手機與桌機版的徽章語意因此不同,若之後要統一需重新設計。
- 需搭配 `env(safe-area-inset-bottom)` 與 `index.html` 的 `viewport-fit=cover`,否則 iPhone Home Indicator 會遮擋或擠壓底部導覽列。
- 頁面主內容(`main`/`.page`)需要在手機版加上對應的 `padding-bottom`,避免內容被固定導覽列遮住。
- 點擊目前已選中的分頁會觸發捲動回頂部,屬於額外的互動行為,未來若分頁內容改為虛擬捲動或分段載入需一併檢查此行為是否仍正確。
